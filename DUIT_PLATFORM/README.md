# DUIT — Найди того, кто сделает

DUIT — сервис поиска и заказа услуг. Пользователь выбирает направление и город, сравнивает предложения и профили, пишет исполнителю, оформляет заказ и после завершения может оставить отзыв. Исполнитель оформляет профиль, публикует услуги с фотографиями, получает заказы и общается с клиентами внутри DUIT.

## Стек

- Python 3.12/3.13
- Django 5.2
- SQLite для простого локального запуска
- PostgreSQL 16 в Docker
- Pillow для пользовательских изображений
- HTML/CSS/JavaScript без тяжёлого frontend-фреймворка

## Ключевые возможности

- регистрация и вход по email или логину;
- роли: заказчик, исполнитель, универсальный аккаунт;
- каталог: 12 сфер, 15 кураторских направлений, 4 города;
- поиск, бытовые синонимы, город, цена, рейтинг, формат и сортировка;
- профили исполнителей, рейтинг, отзывы, опыт и показатели доверия;
- публикация услуги: сфера, направление, цена, формат, описание, до 6 фото;
- избранное;
- внутренние сообщения;
- заказы с датой/временем и контролируемыми статусами;
- отзыв только после завершённого заказа;
- раздельные режимы кабинета заказчика и исполнителя;
- Журнал DUIT с пользовательскими публикациями;
- Django Admin;
- Docker + PostgreSQL во внутренней сети.

## Запуск в VS Code на Windows

Откройте папку `DUIT_PLATFORM` в VS Code и выполните:

```powershell
.\verify_windows.bat
```

Скрипт создаёт `.venv`, устанавливает зависимости, проверяет Django и миграции, применяет миграции, создаёт демо-каталог только если его ещё нет и запускает тесты.

После `DUIT verification PASSED.`:

```powershell
.\start_windows.bat
```

Сайт: http://127.0.0.1:8000/

Журнал: http://127.0.0.1:8000/journal/

Админка: http://127.0.0.1:8000/admin/

### Демо-аккаунты

- Заказчик: `demo_client` / `duit12345`
- Исполнитель: `demo_provider_00_00` / `duit12345`
- Администратор: `admin` / `admin123`

Остальные сгенерированные демо-профили не предназначены для входа.

## Docker

Запустить Docker Desktop, затем:

```powershell
.\start_docker.bat
```

или:

```powershell
docker compose up --build -d
```

Схема:

```text
Browser
  |
  v
Django container :8000
  |
  | internal Docker network
  v
PostgreSQL 16
(no published DB port)
```

`duit_db_data` хранит БД, `duit_media` — пользовательские фотографии. PostgreSQL наружу не публикуется.

## Что важно для защиты

- Django используется как web-framework, ORM, authentication/authorization и backend бизнес-логики.
- SQLite выбран для максимально простого локального запуска; Docker-профиль демонстрирует PostgreSQL.
- Пароли хранятся стандартным password hasher Django, не открытым текстом.
- Критичные права проверяются сервером: чужую услугу нельзя редактировать, собственную нельзя заказать, отзыв требует завершённого заказа.
- Демо-фотографии тематические и имеют локальные fallback-обложки; пользовательские изображения сохраняются в `media/`.
- `seed_demo --if-empty` не уничтожает пользовательские данные при повторном запуске.

## DUIT Pay — учебная имитация оплаты

В проект добавлен собственный демонстрационный платёжный сценарий **DUIT Pay**. Реальные банковские операции не выполняются. Номер карты и CVV никогда не сохраняются в БД.

Тестовые карты:
- `4242 4242 4242 4242` — успешная учебная оплата;
- `4000 0000 0000 0002` — имитация отказа банка;
- срок `12/30`, CVV `123`.

Платёж имеет статусы `pending / paid / failed / refunded`; при отмене уже оплаченного заказа выполняется имитация возврата.

## Мобильная навигация

На мобильных устройствах используется полноценное burger-меню (три полоски → крестик) с каталогом, журналом, кабинетом, избранным, сообщениями, размещением услуги, входом/регистрацией и выходом. Поиск остаётся доступным отдельной мобильной строкой.


## Финальная стабилизация перед сдачей

- исполнитель, который сам оформляет заказ, автоматически получает универсальный режим аккаунта, поэтому его покупка не пропадает из кабинета;
- отменённый или уже возвращённый заказ нельзя оплатить повторно;
- срок тестовой карты проверяется на корректный месяц и истечение;
- услуга с существующими заказами не вызывает `ProtectedError`: она архивируется и исчезает из каталога, сохраняя историю заказа;
- сообщения показывают имя и аватар собеседника, а не только технический username;
- генератор демо-профилей гарантирует уникальные ФИО для 60 исполнителей;
- демо-витрина использует 60 уникальных профилей исполнителей с согласованным полом имени/аватара; каждая из 60 демо-услуг использует отдельный вручную проверенный Pexels photo ID без случайного поиска и без повторов; `verify_windows.bat` автоматически запускает `audit_demo_media`;
- добавлены пользовательские страницы 404 и 500.


## Фото и демо-контент — строгая схема 15/15

Финальная версия использует отдельный тематический фотопул для каждого из 15 кураторских направлений каталога. Услуга больше не может брать изображение из общего пула соседней сферы. Демо-URL используют фиксированные Pexels photo ID и не выбираются случайным поиском. Команда `audit_demo_media` проверяет покрытие 15/15, принадлежность URL точной категории, уникальность URL услуг, уникальность ФИО/аватаров исполнителей и соответствие пола имени/портрета.

Исходный builder скачивает кураторские изображения один раз. После выполнения `prepare_submission.bat` итоговый `DUIT_PLATFORM_OFFLINE_SUBMISSION.zip` содержит весь demo-media локально и для показа демо-фотографий интернет не нужен. Пользовательские фотографии хранятся локально в `media/`.

## Автономные демо-фотографии для сдачи

Финальная сборка умеет кэшировать весь демонстрационный визуал локально:
- 60 кураторских фотографий услуг;
- 60 портретов демо-исполнителей;
- обложки направлений и журнал используют те же локальные изображения.

Один раз на компьютере с интернетом выполните:

```powershell
.\prepare_submission.bat
```

Скрипт скачает фиксированные изображения в `static/demo/`, проверит медиа-аудит и создаст рядом с папкой проекта архив:

`DUIT_PLATFORM_OFFLINE_SUBMISSION.zip`

Именно этот архив можно передать преподавателю. После этого для показа фотографий интернет не требуется. Обычные фотографии пользователей по-прежнему сохраняются в `media/`.


## Stable avatar hotfix

Service demo photos are cached locally. Demo provider portraits use fixed gender-matched RandomUser URLs in the browser and always have a local SVG fallback. They are intentionally not downloaded by `verify_windows.bat`, because RandomUser can return anti-bot responses to Python download clients. This cannot block project startup.
